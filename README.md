# Indo-Japanese Creative Coding Experience

> An experimental Three.js/WebGL experience exploring Indian and Japanese visual storytelling through runtime-generated 3D elements, shaders, atmosphere, animation, and interaction.

## Overview

This project is a browser-based **creative-coding experiment** focused on interactive storytelling, generative visuals, and an imagined fusion of Indian and Japanese visual aesthetics.

The experience creates a fictional environment combining:

* Temple-inspired architecture
* Torii-inspired forms
* Marigold garlands
* Diyas floating on water
* Rangoli-inspired details
* Wet stone and night ambience
* Saffron-toned lighting
* Atmospheric visual effects

The goal is to create an immersive digital environment rather than a conventional static portfolio page.

## Concept

The visual direction explores the contrast between:

### Japanese Visual Stillness

* Minimal composition
* Temple-inspired structures
* Torii forms
* Night ambience
* Restrained visual language

### Indian Visual Warmth

* Marigold flowers
* Diyas
* Rangoli-inspired patterns
* Saffron light
* Water and festival-inspired atmosphere

The result is an intentionally fictional visual world built as an interactive browser experience.

## Creative Coding Philosophy

The project treats code as more than a tool for functionality.

It is also used as a medium for visual expression.

Instead of creating every element as a static asset, the experience explores systems for:

```text
Concept
  ↓
Visual Rule
  ↓
Geometry
  ↓
Material / Shader
  ↓
Lighting
  ↓
Animation
  ↓
Interaction
  ↓
Rendered Experience
```

This approach makes the browser itself part of the creative process.

## Interactive Storytelling

The experience uses motion, lighting, depth, transitions, and environmental details to create a sense of place.

The goal is to make users feel like they are **entering an environment**, rather than simply browsing a webpage.

## Generative Art

The project also explores generative-art principles by treating visual elements as programmable systems.

Instead of only asking:

> What asset should I use?

the development process asks:

> What rule can generate this visual?

This creates opportunities for variation, animation, and runtime-controlled visuals.

## WebGL & Performance

WebGL experiences can be demanding, so the project considers different device capabilities and rendering conditions.

The implementation includes adaptive handling and a fallback path for environments where WebGL is unavailable.

This makes performance part of the design process rather than something considered only at the end.
